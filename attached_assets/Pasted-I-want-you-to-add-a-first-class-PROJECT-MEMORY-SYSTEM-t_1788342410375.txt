I want you to add a first-class PROJECT MEMORY SYSTEM to FilmStudio AI inspired by the way InVideo AI Agents use Context and Notebook.

Do NOT make this a simple notes page.

The purpose is to give the AI Video Director persistent production memory so it can understand a project, maintain continuity, respect locked decisions, and use approved references when planning and generating images/videos.

BUILD TWO CONNECTED SYSTEMS:

==================================================
1. PROJECT CONTEXT
==================================================

Add a "Context" area to every FilmStudio project.

Context represents the ACTIVE PRODUCTION TRUTH for the current project.

Create structured sections:

A. ABOUT THIS PROJECT
- Project title
- One-line description
- Full description
- Creative objective
- Audience
- Desired emotional effect
- Genre
- Format
- Aspect ratio
- Duration
- Resolution
- Platform
- Overall visual direction

B. SPINE
The project's primary source material.

Support:
- Audio/music track
- Lyrics/transcript
- Script
- Story
- Reference document
- Timing information
- Beat markers
- Section markers

The agent must treat the selected spine as authoritative.

For music videos:
- Never invent a replacement song.
- Preserve the uploaded track.
- Understand duration.
- Understand vocal timing where available.
- Allow sections such as intro, verse, hook, bridge, outro.
- Allow exact timestamps.

C. PICTURE / STORY
Store:
- Story concept
- Narrative
- Scene description
- Section plans
- Shot plans
- Performance direction
- Camera direction
- Blocking
- Environment
- Lighting
- Action
- Continuity requirements

D. CHARACTER

Store:

Allow the project to define compositing layers.

Layer D = VFX

J. LOCKS
This is extremely important.

Allow the user or agent to explicitly LOCK decisions.

Examples:

IDENTITY LOCK:
"Josh's identity must always come from the approved identity references."

FACE LOCK:
"Use the approved face reference. Do not substitute a generated face."

WARDROBE LOCK:
"Red/black long-sleeve jersey, black pants and white sneakers."

LOCATION LOCK:
"Wet urban street at night."

CAMERA LOCK:
"Locked-off camera."

STYLE LOCK:
"Photorealistic cinematic night photography."

A lock must be treated as a hard constraint by the generation/planning system.

Every generation request should automatically retrieve relevant locks before creating prompts.

K. ACCEPTANCE CRITERIA
Allow explicit project-level success conditions.

Examples:
- Face identity must match approved reference.
- Hair must remain red-tipped.
- No sunglasses.
- Jersey must remain unchanged.
- Officers must remain in background.
- Camera must remain locked.
- No additional faces.
- Lip sync must match audio.
- Character must remain bottom-right.
- Final shot must end before the vocal cut.

The agent should use these criteria during output review.

4. AI MEMORY RETRIEVAL
==================================================

This is the most important part.

Whenever the AI Video Director performs a task, automatically retrieve relevant Context + Notebook information.

Example:

User:
"Create the next shot of Josh walking through the street."

The agent should automatically retrieve:

- Character identity lock
- Approved face references
- Hair reference
- Body reference
- Tattoo reference
- Current wardrobe
- Current location
- Current lighting
- Current camera rules
- Current story/section
- Current continuity rules
- Previous approved shot
- Relevant rejected outputs

Then construct the generation prompt from that information.

The user should NOT have to manually paste the same information every time.

==================================================
5. MEMORY PRIORITY SYSTEM
==================================================

Implement priority ordering:

1. HARD LOCKS
2. APPROVED AUTHORITATIVE REFERENCES
3. ACCEPTANCE CRITERIA
4. ACTIVE CONTEXT
5. APPROVED NOTEBOOK ENTRIES
6. PREVIOUS APPROVED GENERATIONS
7. GENERAL PROJECT NOTES
8. USER'S NEW CREATIVE INSTRUCTION
9. MODEL DEFAULTS

However, a new explicit user instruction should be able to intentionally override a previous non-locked decision.

Never silently override a HARD LOCK.

If a user request conflicts with a lock, tell the user:

"That conflicts with the current [LOCK]. Do you want to change the lock?"

==================================================
6. AGENT BEHAVIOR
==================================================

The AI Video Director should treat Context and Notebook as production memory.

Before generating anything:

1. Understand user request.
2. Identify required memory.
3. Retrieve relevant Context.
4. Retrieve relevant Notebook entries.
5. Retrieve authoritative references.
6. Retrieve locks.
7. Retrieve acceptance criteria.
8. Build a production plan.
9. Generate prompt(s).
10. Generate asset(s).
11. Review result against acceptance criteria.
12. If failed, explain which criteria failed.
13. Automatically propose a regeneration.
14. Never overwrite approved assets without explicit permission.

==================================================

==================================================

Allow the agent to suggest Notebook entries based on production activity.

User says:

Type:
Continuity Rule

Rule:
"Sunglasses OFF for Josh lip-sync shots."

Status:
APPROVED

Similarly, if the user approves a generated character sheet:

Automatically offer:

"Save this as the authoritative character identity reference?"

==================================================
8. APPROVAL SYSTEM
==================================================

Everything important should have an approval state.

The agent must distinguish:

GENERATED
REVIEWING
APPROVED
LOCKED
REJECTED

Only APPROVED/LOCKED assets should become strong continuity references.

Rejected outputs should remain available as negative evidence.

Example:

Rejected:
"Face drifted toward generated face."

Store that as a continuity failure associated with the generation.

14. DO NOT JUST BUILD THE UI
==================================================

The Context and Notebook data MUST actually connect to the AI Video Director.

The following must be true:

Creating a lock changes generation behavior.

Approving a reference changes retrieval priority.

Changing wardrobe changes future shot prompts.

Rejecting a face prevents it from becoming an identity reference.

Approving a character sheet makes it available to future generations.

Changing project location updates future scene generation.

Acceptance criteria are used during output review.

Notebook knowledge can become active Context.

Context can be saved back into Notebook.
